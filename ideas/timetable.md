# タイムテーブル：Project: NEXUS_WAR [Turn-Based Edition]

1ターン15分 × 8スロット（合計120分）の進行管理表。

## 進行フロー (共通)
1. **0-10分: 議論 & 調査**: 共有コンソールに流れる前ターンの結果を元に議論。
2. **10-14分: アクション入力**: 各自 3 AP分のアクションをプロンプトに入力。
3. **14-15分: ターン解決 (Sync)**: システムが全アクションを計算し、次のターンの初期状態を反映。

## タイムライン

| ターン  | 時間  | 状況 / イベント                             | PLがすべきこと                          |
| :------ | :---- | :------------------------------------------ | :-------------------------------------- |
| **T1**  | 09:00 | **[開幕]** 全システム暗号化。               | 被害状況の把握 (`status`)。             |
| **T2**  | 09:15 | **[通信隔離]** 外部NWを遮断するか否か選択。 | 遮断すれば安全だが、復旧速度激減。      |
| **T3**  | 09:30 | **[デッドライン]** 顧客情報の流出が始まる。 | ハッカー1名による加速工作が発生。       |
| **T4**  | 09:45 | **[監査開始]** 誰かの端末を強制精査できる。 | 疑わしいPLの `audit` を要求。           |
| **T5**  | 10:00 | **[中間報告]** 生き残りサーバーの確定。     | **[Hacker]** 偽のログで冤罪を仕掛ける。 |
| **T6**  | 10:15 | **[逆探知]** 物理端末の特定チャンス。       | 正解すればハッカーのIDが1つ割れる。     |
| **T7**  | 10:30 | **[最終攻防]** データの抽出率が90%に。      | 全員で一斉 `lock` を行うか。            |
| **T8**  | 10:45 | **[決断]** 隔離・修復・または降伏。         | 最終投票（隔離コマンドの実行）。        |
| **End** | 11:00 | **結末判定 (Ending)**                       | スコアに基づきマルチエンディング。      |

## システム側のアクション・ログ出力例 (T2終了時)
```text
[09:15:32] INFO: PL1 executed 'status' (0AP)
[09:16:10] INFO: PL2 executed 'secure_scan' (1AP)
[09:16:45] WARN: Unexpected file access in /etc/shadow by UID:1005 (??? AP)
[09:17:00] CRITICAL: Data transmission to 103.x.x.x started.
```
- この「UID:1005 (誰かのアカウント)」が、ハッカーの正体を探る決定的な手がかりとなります。
