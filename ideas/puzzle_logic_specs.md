# 脆弱性連鎖ロジック：スイスチーズモデル

単一のアクションでは漏洩は起きません。複数のPLが「リスクのある選択」を重ね、それらが**特定の順番で繋がった時のみ**、データ漏洩（System Breach）が発生します。

## 1. 漏洩までの状態遷移 (State Transition)

システムは以下の 4 ステップを経て崩壊します。

| 状態                | 説明                                                      | 発生条件                                              |
| :------------------ | :-------------------------------------------------------- | :---------------------------------------------------- |
| **Healthy**         | 正常。攻撃は防がれている。                                | 初期状態                                              |
| `msg <USER> <TEXT>` | **1 AP 消費**。指定した相手にのみ秘密のメッセージを送る。 | -                                                     |
| **Exposed**         | **[第1の穴]**: 内部にウイルスが侵入。                     | PL (A) が脆弱な設定（例：RDP開放）を選択。            |
| **latential**       | **[第2の穴]**: ウイルスが権限昇格に成功。                 | **Exposed 状態** かつ PL (B) が検証なしの復元を実行。 |
| **LEAKING**         | **[致命的な穴]**: データの外部流出が開始。                | **Latential 状態** かつ PL (C) が外部FWを全開放。     |

## 2. 脆弱性連鎖の例 (Breach Chain)

### パターンA：バックアップ汚染ルート
1.  **PL2 (開発)**: `Fast Restore` を実行（ウイルス入りの古いバイナリを戻してしまう）。
2.  **PL1 (管理者)**: PL2の作業を確認せず、全システムの整合性チェックを `Skip` する。
3.  **PL3 (NW)**: 通信速度回復のため、IDS（侵入検知）を一時停止する。
4.  **結果**: ウイルスがNW側から堂々とデータを外出しし、**「データ漏洩」**が確定。

## 3. ミステリーとしての解析
- プレイヤーは、事後調査（Audit）によって、**「誰のアクションが、どのタイミングで、次の過失に繋がったか」**を特定しなければなりません。
- 「自分がAをしたから、Bさんのミスが致命傷になったのか...？」という、**連鎖的な罪悪感**が議論を加速させます。

## 4. 勝利（回避）のロジック
- 連鎖が「LEAKING」に達する前に、**連鎖のどこか1つを「遮断（Fix）」**できれば、漏洩は止まります。
- 例：PL3がIDSを止めても、PL1が整合性チェックをしっかり行っていれば、漏洩は防げます。
- 誰を「追放」するかではなく、どの「連鎖」が今起きているかを見極め、適切な修正コマンドを打てるかどうかが勝負です。
