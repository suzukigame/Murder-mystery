# ゲーム進行・成長・アンロックシステム（構想案）

本ドキュメントでは、Steam展開を見据えたプレイヤーの「実績」「レベル」「報酬」による継続的なプレイ動機を高めるシステムの構想をまとめます。

---

## 1. 成長システムのコンセプト

「Murder Mystery」という性質上、ステータス（攻撃力など）を上げることはできませんが、**「見た目の豪華さ」「使えるキャラクターのバリエーション」「ターミナル体験の深度」**を拡張することで、熟練エージェントとしての誇りを感じられるようにします。

---

## 2. アンロックの対象（アイテム・要素）

### キャラクター・スキン
- **基本キャラ**: 初回から使用可能（エージェント Alpha, Sigma など）。
- **解除キャラ**: 
  - 例：「ハッカーで3回完全勝利」→ 伝説のハッカー『Zero』がアンロック。
  - 例：「全ての社員役職を1回ずつプレイ」→ 汎用エージェントの別スキンがアンロック。
- **Steam連携**: Steamインベントリアテムとして配布することで、トレード可能にすることも視野。

### ターミナル・カスタマイズ（環境アイテム）
- **UIテーマ**: 背景色、フォント、走査線エフェクトの強弱。
- **起動ログ**: ゲーム開始時の「SYSTEM BOOT」のメッセージをカスタマイズ可能に。
- **特殊エフェクト**: スキル使用時に固有のキラリと光るエフェクトや、特殊なフォントでのログ出力。

| 実績名                     | 達成条件                                     | 報酬                                   |
| :------------------------- | :------------------------------------------- | :------------------------------------- |

## 4. 技術的な拡張点と保存方法 (Steam展開を見据えて)

キャラクターの解放（アンロック）状態や実績を保存するためには、**「ユーザー・データの永続化」が必須**になります。現状のNode.jsサーバーのメモリ管理では、サーバー再起動で消えてしまうためです。

### 案A: 【無料・最速】ブラウザの LocalStorage を使う
*   **概要**: プレイヤーのブラウザ自体にデータを保存します。
*   **メリット**: サーバー開発不要、DB費用ゼロ、完全に無料。
*   **デメリット**: 別のPCやスマホからアクセスした時はデータが引き継がれません。また、ブラウザのキャッシュを消すと実績も消えます。ブラウザの開発者ツールで簡単にチート（全開放）されてしまいます。
*   **適しているケース**: Steam展開「前」の、ブラウザでサクッと遊んでもらうプロトタイプ段階。

### 案B: 【無料枠あり】BaaS (Firebase / Supabase) を導入する
*   **概要**: Googleの **Firebase** や、OSSの **Supabase** などのクラウドデータベースを使います。
*   **メリット**: 無料枠が非常に大きく（Supabaseなら月間50万回アクセスまで無料等）、個人開発レベルなら実質ずっと無料で運用可能です。スマホでもPCでもデータが同期されます。
*   **デメリット**: ログイン機能（Googleログインやメール認証など）を実装する必要があります。
*   **適しているケース**: 本格的にWebサービスとして公開し、ユーザーに長く遊んでほしい場合。

### 案C: 【Steam特化】Steamworks API (Steam Cloud / Achievements)
*   **概要**: Steamで配信する前提なら、ユーザー管理もデータ保存も**すべてSteamのサーバーに丸投げ**できます。
*   **メリット**: DB費用ゼロ。プレイヤーは「Steamでログインしている」だけでよく、専用の会員登録が不要です。Steamの実績機能と完全に連動できます。
*   **デメリット**: Steam専用になるため、通常のWebブラウザ（スマホ等）からは遊べなくなります。
*   **適しているケース**: Web版は「お試し・プロトタイプ」と割り切り、本番はSteamでのみリリースする場合。

---

### おすすめのアプローチ（ロードマップ）
1.  **フェーズ1（今すぐ）**: `LocalStorage`（案A）を使って、簡単な条件（例：3回プレイする）でキャラクターが解放されるロジックとUIだけを作ってしまう。
2.  **フェーズ2（Web公開時）**: 必要なら `Supabase`（案B）を導入してデータ消失を防ぐ。
3.  **フェーズ3（Steam移行時）**: セーブデータの保存先を `Steam Cloud`（案C）に切り替える。

このように、まずは一番簡単な「LocalStorage」で**「アンロックされる体験（UI）」そのものを作る**のが最も確実でモチベーションが上がる進め方です。
